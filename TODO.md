### Overview Model
Full review 2026-09-26 against SME's `overviewModel` module, its meta model (every rule) and the A12 2026.06 BA doc: "Overview Model: gap review" in `docs/sme-reference-comparison.md` (17 numbered gaps, a rule-by-rule coverage table and the suggested order; the numbers below are its gap numbers). The editor covers every SME setting; what is left, in build order:
- **Gap 1, first: Enumerated string filter has no field list.** `FilterStringFieldsMultiSelectPanelController` only toggles the feature and edits the page size, so `enumeratedStringFilter.fields` (used by `ProductBook_OM`, `ProductFood_OM`, `ProductMovie_OM`, `ProductSingle_OM`) cannot be seen or edited, and enabling it on a new model writes an invalid empty object. Add the field list (String fields only) and the four rules (not empty when enabled, unique, valid reference, page size required).
- **Gaps 2, 3, 10: values that are written wrong or not at all.** Action Column Width is edited as an integer although real values are 0.3-0.5 (min 0.3, one decimal; the field shows `0` and the first edit destroys the value); a new model serializes `enableFilter`/`showFullTextSearch`/`rowActionGroup`/`subHeaderBox`/`footerBox` as `null` and has none of SME's default sub-header elements; the Filter panel shows defaults (`all_columns`, both switches on) that are not written, so `OverviewFilterModeRequiredValidator` complains about a mode the combo shows; Row Height shows 32 but stays unset (SME pre-fills 49 for infinite scrolling); Paging Size defaults to 10 (docs and 51 of 80 files: 50). Add the missing required checks (Paging Size for pagination; Row Height and Action Column Width for infinite scrolling).
- **Gaps 7 then 6: binding purpose, then the sub-header rules.** Derive Available/Selected Items purpose from the Form `Binding` components (SME `isBindingOverviewModel`) before porting the six "element not allowed while the feature is off" rules, "No filter element is added" and "Only one filter", which SME skips for binding overviews. - **Gap 8: expression columns are not validated at all.** Name and Expression are not required, the editor has no `setValidator`, there is no header label/icon warning, and a blank expression column reloads as a reference column. - **Gaps 9, 11, 12, 13: plain validators** (each with `*_invalid.json` fixtures like the existing ones): `suffixRef` reference/`indexed`; sortable column needs a preferred sorting, attachment/multi-select column needs a display mode; column header/content style references (must exist in `content.styles`, unique; the Styles panels are free-text lists, make them pickers) and `content.styles` uniqueness; Initial Sorting duplicates and non-sortable columns (picker: sortable reference columns only); filter section label required; Context Menu group without an action; `export_excel` warnings (CDM only / non-repeatable CDM).
