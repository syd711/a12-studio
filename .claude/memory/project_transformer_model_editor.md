Built 2026-10-03 from TODO "implement the transformer model editor": `transformermodel` packages in models / models-validation (6 validators) / ui (editor, 6 panels, `TransformerRun`), registered in `ModelType`/`model-versions.json`/`ModelFactory`/`NewModelFactory`/`ValidationService`/`EditorFactory`/`Icons`, Settings = the generic `ModelSettingsDialog` (hides supported characters + references). Full feature table, deviations and the not-done list: "Transformer Model: built" in `docs/sme-reference-comparison.md`. Main open follow-up: no other editor can pick the generated Document Model (it exists only after a run).

**Why / traps worth knowing**
- **The SME checkout lags the installed SME for this type** (`TransformerConfigModel` 28.4.0 checkout vs 29.4.0 installed: `PatternErrors.action/replacement`, 7 uniqueness rules, no `Cmd.genDocModelName`, backend `/discover`). Read rules from `<installation>/bin/simple-model-editor/<v>/static/models/TransformerConfigModel.json`; the `[a12Type->superType]` map is only in `TransformerConfigModel.validation.js` (grep `superType`). General rule already in [[installed-sme-backend-and-client]] - this was a fresh case of it.
- **The installed editor gets its suggestion lists from the backend** (`xsd:rootElements/simpleTypes/elementPaths/patterns`, `enumValue`, `enumFieldPathByValue`) = `POST /api/transformer/discover`; `/transform` and `/discover` both take `{inputResources:[{type:"XSD",name,content}], transformationConfig:<the model JSON>}`. Probe it by starting `sme.jar --server.port=N` with the installation's java and POSTing from python (`urllib`); stop the process afterwards. Findings: discover works with no `rootElement` (and then returns no element paths); transform without one answers only "This field is required."; a main XSD name without `.xsd` still works; the backend never answers non-200 for transformer failures, they come as `success:false` + issues.
- **`ProjectItem`/`ProjectFileFilter` only know `*.json` + folders** - XSDs are invisible to the project tree and `Project` has no resources concept, hence `ProjectResources` (scans the folder). And **`ProjectItem.getProjectFolder()` returns the item's own file when the item has no parent** (a test built with `new ProjectItem(file)`): use `Studio.getCurrentProject().getFolder()` first (what the validators' `ValidationContext.project()` does), fall back to the item.
- Test traps: `Parent.lookup` does not see into a `TitledPane` that has no scene (no skin) - search `getContent()`; `FxTestSupport.onFx(obj::method)` is ambiguous (Callable vs Runnable) - use a lambda; `@TempDir static` + `@BeforeAll` works for the backend test; the 4 backend tests skip themselves without an installation (check `skipped="0"`).
- **Offscreen snapshot works headless here** (the FX toolkit starts, `skipped=0`): put the loaded FXML root in a `new Scene(root, w, h)`, `applyCss()`+`layout()` twice per selected tab, `root.snapshot(...)`, copy the `PixelReader` into a `BufferedImage`, `ImageIO.write` a PNG, then Read the PNG. That is how the layout was checked (throwaway test, deleted); worth repeating for any new editor since no one can open the app here.
