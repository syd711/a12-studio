**Baseline (2026-09-21, end of day): the whole suite is green** - 1457 tests, 9 skipped, 0 failures (`./gradlew test --continue --offline` in a mirror, see below). The two tests that used to be red (`QueryValidatorsTest.sortFieldReferenceValidatorReportsMissingField`, `ApplicationGroupFeatureTest.prefixesEveryModelAndRewritesReferences`) were stale fixtures, fixed 2026-09-21: a Query sort fixture in the old `sortBy`-wrapper shape (on the wire `field`/`direction` sit directly on the sort entry, `QuerySort` uses `@JsonUnwrapped`), and `testing/workspaces/basic/models/QueryModel.json`, which was removed in 43a6a3f0 while the application-groups test still read it (the test now writes its own Query Model). **Any red test is therefore a regression**, no exemption list exists. When a fixture-reading test fails, check first whether the fixture still exists / still has the wire shape - `git log -- <fixture>` - before suspecting the code.

**Why:** both had been carried as "known failures" for days, which made a real regression indistinguishable from them.

**How to apply:** run the affected module (`./gradlew :a12-studio-models-validation:test --offline -q`), and for `a12-studio-ui` use the mirror below. Tooling: `FxTestSupport` (`a12-studio-ui/src/test/.../editors/formmodel/`) starts a JavaFX toolkit and stubs `Studio`'s static root controller/project so FXML + controllers can be driven in tests; such tests skip themselves without a display (`assumeTrue(toolkitAvailable)`), so check `skipped="0"` in the XML report when a new FX test must really have run.

**Locked `build/` on Windows (seen 2026-09-19, again 2026-09-21):** `:a12-studio-ui:processResources` can fail with `Failed to clean up stale outputs` / `Couldn't delete ...\a12-studio-ui\build\resources\main\...\Model-Overview.png ... used by another process` - something outside Gradle (the IDE) holds an icon open, so no UI test can run in the real tree. The non-UI modules still test fine in place. To run UI tests, mirror the tree to a short path and run there (the scratchpad path is too long for this repo's fixtures on Windows): PowerShell `robocopy C:\workspace\a12-studio C:\wt5 /MIR /XD build .git .gradle .idea out Output node_modules /XF *.log` (exit code 1 = success), then `./gradlew test --continue --offline` in `C:\wt5` (about 5 minutes for the full suite; run it in the background).

**Debounced saves vs. `@TempDir`:** a JavaFX test that types into a field whose panel saves through a `Debouncer` (150 ms) can leave a pending save that fires after the test and races JUnit's temp-dir deletion, surfacing as `JUnitException: Failed to close extension context` on whichever test ran last - and only in a full run, not in isolation. Fix: an `@AfterEach` that calls the controller's `destroy()` (its `debouncer.shutdown()` cancels pending saves) and then flushes the FX queue (`FxTestSupport.onFx(() -> { })`); see `QueryAggregationPanelTest`.

**A JavaFX test that opens editors must close them again (seen 2026-09-21):** an editor opened through `TabPaneController.modelOpened` (or `EditorFactory.create`) registers itself on the application-wide `StudioEventManager` and only unregisters on `fireModelClosedEvent(item)`. `TabPaneControllerTest` first left two Query editors registered, and in the next full run an unrelated `QueryAggregationPanelTest` failed once (its saved file was `null`; it passed alone and after the cleanup was added). Fire `ModelClosedEvent` for every opened item in an `@AfterEach`, and reset any static you set on `Studio` (`currentProject`, `validationService`) in `@AfterAll`. Editors also need a real loaded `Project` (`project.load(dir)`) and, for the Query editor, `Studio.validationService` set by reflection - `FxTestSupport`'s empty `Project` has no settings.
